# 🛠️ 代码修复技术规划

[English](CODE_FIXES.md) | [简体中文](CODE_FIXES.zh-Hans.md)

本方案以 [开发规范](../zongsoft.csharp.guidelines.md) 和当前 Global AnalyzerConfig 为依据，覆盖已有诊断及尚未自动检测的规范要求。目标是让能够确定正确结果的违规提供可预览修复，让存在业务选择的违规提供有边界的辅助操作。不能把所有违规都承诺为“一键修复”：设计意图、公共兼容性、资源所有权和翻译内容需要开发者判断。

诊断行为、例外及 VS 帮助入口以 [规则列表](../RULES.zh-Hans.md) 为准；本文只维护修复实现与后续规划。

## ✅ 1. 已交付的第一阶段

| 规则 | 修复动作 | 保留的约束 |
| --- | --- | --- |
| [ZS0005](../RULES.zh-Hans.md#zs0005) | 移除未使用的引用 | 再次核对编译器 CS8019；保留所有普通命名空间引用、正在使用的引用、注释和条件编译指令；不整理其他引用 |
| [ZS2003](../RULES.zh-Hans.md#zs2003) | 在语句组之间插入空行 | 只修改诊断边界；保留缩进、CRLF/LF、注释和条件编译；跨行尾注释之后再插入空行，不格式化整个文件 |

两个动作均提供英文和简体中文标题，支持单处修复以及文档、项目、解决方案范围的 Fix All。批量操作只处理所选规则，不隐式修复另一条规则。

实现位于 [fixes/src](fixes/src)，随 `Zongsoft.CodeAnalysis` 同一个 NuGet 包分发。无需另装 VSIX。Visual Studio 的快速操作由宿主呈现，通常通过警告位置的灯泡或 `Ctrl+.` 打开，再预览并应用修复；菜单文字随 IDE 语言和版本变化。[Microsoft 分析器说明](https://learn.microsoft.com/en-us/visualstudio/code-quality/roslyn-analyzers-overview?view=visualstudio)

本阶段验证包括真实 nupkg 中的 MEF 导出、33 个修复用例、原有 55 个编译消费用例，以及 .NET 10 SDK 的 `dotnet format analyzers` 实际发现和执行。修复后检查精确文本、诊断消失和编译结果。尚未在 VS2026 界面中逐项点击灯泡、预览和撤销，发布验收仍应执行该步骤。

## 🧭 2. 修复能力分级

| 等级 | 使用方式 | 批量策略 |
| --- | --- | --- |
| A：结果确定 | 保持语义的局部文本或语法修改，提供预览 | 通过冲突、幂等和跨项目测试后开放 Fix All |
| B：需要选择 | 开发者选择目标名称、资源项或迁移方式，再产生可预览修改 | 默认单处；只有选择能稳定复用时才开放受限批量 |
| C：需要设计判断 | 提供诊断位置、原因、规范链接和可操作建议 | 不注册会猜测业务意图的自动修复 |

抑制诊断不是修复，不计入修复覆盖率。规则未触发、被本地配置关闭或属于允许的例外时，不额外建议把合规代码改成另一种风格。

## 📋 3. 当前诊断的实施矩阵

| 诊断 | 实施路线 | 验收重点 |
| --- | --- | --- |
| `ZS0005`、`ZS2003` | 已实现，A级 | 继续维护注释、指令、同一行多处变更及三个批量范围的回归 |
| `IDE0009` | 复用 SDK 的成员访问限定修复 | 为属性、方法、事件补 `this.`；不把规则扩展为给所有字段补 `this.` |
| `IDE0049` | 复用 SDK 的内置类型关键字修复 | 保留类型和表达式语义；通过 IDE 或 `dotnet format style` 验证，不能仅依赖构建 |
| `IDE0065`、`IDE0161` | 复用 SDK 的 using 位置、文件范围命名空间修复 | 嵌套或多命名空间、类型解析变化、条件编译等不能安全转换时不强制转换 |
| `IDE1006` | 优先复用 SDK 命名修复和 Roslyn Rename，B级 | 检查重名、重载、接口实现、跨文件引用；公共 API、序列化、反射、配置文件引用需人工确认，不能只替换标识符文本 |
| `IDE0055`、`IDE2001` | 复用 SDK 局部修复，增加例外回归 | 保留规范允许的指令缩进和紧凑 try/catch/finally 及合规的两语句方法／lambda 块体；不把整个文件的格式化当作精确修复 |
| `ZS1304` | 下一阶段：固定资源键到现有 Designer 属性，满足全部语义条件时为A级，否则B/C级 | 确认同一个资源管理器、资源键、可访问属性、返回类型及区域性语义；没有匹配属性时不猜测 |
| `CA1303` | 先提供“使用现有资源属性”；再设计“提取到 ResX”，B级 | 区分用户文本与机器标识；选择资源文件和资源名，保持格式占位符、参数求值及异常参数名 |
| `CS4014` | 按上下文提供建议，B/C级 | 加 `await` 可能改变返回类型、异常传播、调用链和执行顺序；明确有监督的后台操作不能机械改成等待 |
| `CA2012` | 按 ValueTask 使用方式提供有限操作，B/C级 | 区分单次等待、重复消费、保存和转 Task；不机械添加 `.AsTask()` 或重复等待 |
| `ZSS0055`、`ZSS0056`、`ZSS2001` | 保持抑制器职责 | 它们允许约定内的代码，无需反向“修复” |
| 已关闭的 `IDE0001/2/3`、`IDE0005`、`IDE0130`、`IDE0210/11`、`IDE0290` | 不新增对应批量动作 | 保留 `global::`、既有入口形式等有意选择；未使用引用由 ZS0005 负责 |

Global AnalyzerConfig 中其余现代语法建议优先复用 SDK 已提供的操作：`var`、目标类型 `new`、自动属性、表达式体、空值合并、模式匹配、初始化器、集合表达式、只读成员、局部函数等。按当前 SDK 逐项建立样例验证操作是否存在及是否符合配置，不复制 SDK 的完整修复实现，也不将建议统一升级为错误。

## 🧩 4. 尚无诊断编号的规范要求

以下矩阵覆盖开发规范各章节。只有把措辞转化为可测试的条件后才分配新的 `ZS` 编号；“尽量”“适当”等原则不能直接变成无例外的警告。

| 规范范围 | 检测与修复方案 | 限制 |
| --- | --- | --- |
| 1 基本原则；2 命名语义与类型后缀 | 已配置的大小写复用 IDE1006；评估可确定的类型后缀检查 | 业务命名、职责表达和缩写语义属于C级 |
| 3.1 文件、编码、换行、一文件一主要类型 | EditorConfig/Git 属性负责编辑器与仓库约束；文件拆分采用独立重构操作 | 不借局部修复改变整个文件的 BOM/EOL；分部类型和生成代码需豁免 |
| 3.2 using 分组、组内排序 | 新增只处理安全引用区段的分析器和修复器 | 按实际依赖分组及规范排序；注释、指令、extern alias 形成边界，不能跨边界排序 |
| 3.2 禁用 using 别名 | 通过别名符号查找实际引用，转换为 `global::` 完整限定名后移除别名 | 验证泛型、嵌套类型、属性名称、`nameof` 常量值和不同条件分支；值或绑定变化时不给自动修复 |
| 3.2 正式项目慎用 global using；测试 Global.cs 例外 | 先定义项目类型与例外的可读取配置；必要时提供预览迁移 | 全局引用影响多个文件，不能仅移除 `global`；不要移动测试允许的全局引用 |
| 3.3 成员分段与 region | 检查可明确的重复或空分段；按选中范围提供辅助操作 | 不自动重排字段初始化顺序、partial 成员或承载说明的 region |
| 3.4 空格、表达式体和空行 | 复用 SDK 格式规则与 ZS2003；新增规则需先明确例外 | 赋值组仅在连续超过两条且紧接条件或循环时要求空行；允许连续简单无花括号 if 紧凑排列；保留其他独立控制结构的分隔，不机械拆分声明、调用、返回或关联子句 |
| 4 注释与 API 文档 | 复用编译器文档诊断；可补与签名一致的参数节点骨架 | 不生成虚假的说明、示例、线程安全承诺或版权信息 |
| 5.1 成员访问、局部变量与属性 | 复用成员限定、var、自动属性修复；再评估 `field` 支持 | 不能删除被反射或其他成员使用的后备字段；保留验证、通知、初始化和属性特性 |
| 5.2 现代语法 | 复用 SDK 操作并尊重项目语言版本 | 不自动升级 SDK；集合转换保持具体类型、比较器、容量和枚举时机 |
| 5.3 字符串、空值、集合 | 复用可以证明等价的语法简化；文化比较和空值语义提供建议 | 不用经验规则猜测是否需要大小写、区域性比较或改变延迟执行 |
| 5.4 结构与相等性 | 复用只读结构等 SDK 建议；检查相等成员的一致性 | 相等字段、哈希组成、可变性和数值容差必须明确后再生成 |
| 6.1–6.5 职责、继承、扩展点、服务装配与兼容性 | 单独规划架构/契约检查；诊断附调用链和规范链接 | 默认C级，不能一键拆接口、改依赖方向、注册服务或修改公开契约 |
| 7.1 异步与取消 | SDK 诊断加取消传递、异步签名的专用检查 | `async`/`await`、ConfigureAwait 和取消令牌均需上下文，不全库替换 |
| 7.2 参数与异常 | 对等价模式提供 ThrowIfNull 等转换 | 保留异常类型、参数名、表达式求值次数和现有本地化消息 |
| 7.3 所有权与并发 | 可验证的作用域问题给建议；结合生命周期审查 | 不自动延长 using 生命周期、释放共享对象或改锁策略 |
| 7.4 本地化 | 按下一节分阶段实现；生成器配置、资源同步可单独检测 | 日志、交互和异常文本都在范围内；协议键、路径、资源标识不能按字面量一刀切 |
| 8.1 项目配置与依赖 | 独立 MSBuild/仓库检查处理项目文件，保留项目覆盖 | 不在 CodeFix 中升级包、切换中央包管理或写发布凭据 |
| 8.2 测试与文档；8.3 自动检查 | 校验测试/文档入口和配置一致性；行为测试由开发任务完成 | 不用自动生成空测试或关闭规则来“修复”质量要求 |
| 9 依据与参考 | 维护规范链接和示例验证 | 属于文档维护，不是源码 CodeFix |

## 🌐 5. 本地化修复的具体设计

### 5.1 ZS1304：使用现有强类型属性

1. 从 `IInvocationOperation` 获取目标 ResourceManager、常量键、显式 CultureInfo 参数及当前返回值使用方式。
2. 在当前项目和可访问的项目引用中定位实际 Designer 类，核对生成属性的键和 ResourceManager 来源；不能仅按 `Resources` 类名或属性名猜测。
3. 只有一个可访问且语义等价的属性时提供直接替换；类型冲突使用 `global::`，不创建 using 别名。多个等价候选以独立菜单项供选择。
4. 显式 culture、具有副作用的接收者、流与对象类型差异、默认资源回退、强制转换或可空行为无法证明等价时不提供直接替换。
5. 首版限定为已有属性；资源缺失时提供规范链接及生成说明。随后才评估同一映射的文档/项目批量修复。

### 5.2 CA1303：复用或提取资源

第一步仅复用现有资源：按中性资源值匹配候选，并由开发者选择具有正确用途的键。文本相同不等于用途相同，不能无条件复用。

第二步才实现提取：确定目标中性 ResX、合法且不冲突的键、用途说明和占位符；用 `Solution` 修改源码及纳入工作区的资源文档，显示完整预览。不覆盖翻译，不伪造翻译；翻译工作单独安排并利用中性资源回退。

`ResXFileCodeGenerator` 是 Visual Studio 自定义工具，不是普通 `dotnet build` 会执行的生成目标。Roslyn 的可移植 CodeFix 也不能承诺在 VS 和 CLI 中统一调用该工具。因此首版不手写 Designer、不在分析期间启动 VS、不通过临时关闭诊断绕过资源生成。

完整提取流程需要先验证 VS 资源生成集成：资源修改、真实自定义工具生成、源码替换是否能形成可预览和可撤销的一次操作。若纯 NuGet CodeFix 无法满足，就明确提供“编辑 ResX → 运行自定义工具 → 使用生成属性”的分步流程；只有确有必要时另行评估可选 VS 扩展。CLI/CI 继续使用已提交的 Designer 文件，不能暗中引入另一套生成器。

## ⚙️ 6. 实现结构与宿主边界

- `analyzers/src` 分析器程序集只依赖编译器 API；`fixes/src` 依赖 Workspaces，包含 `CodeFixProvider`、本地化标题和修复算法。两个 DLL 及各自卫星资源同包发布，不夹带宿主的 Roslyn/MEF 程序集，不增加业务运行时引用。
- 每个动作使用稳定的诊断编号和 equivalence key。优先返回 `ApplyChangesOperation`，在不可变文档/解决方案上产生修改，遵循取消，不在注册菜单时写文件、执行构建或调用网络。
- 文本布局修复使用最小 `TextChange`；语义修复使用 SyntaxEditor/DocumentEditor、SemanticModel、符号匹配及必要的重命名 API。Formatter/Simplifier 只限于新增节点，并验证不会移除要求保留的 `global::`。
- 第一阶段使用 `WellKnownFixAllProviders.BatchFixer` 合并不冲突的文档修改。涉及重叠变更、符号迁移或同一资源文件的多个写入时，设计独立 FixAllProvider，在同一 Solution 快照中去重、排序并检查冲突，不把逐项动作机械并行执行。[Microsoft BatchFixer 文档](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.codefixes.wellknownfixallproviders.batchfixer?view=roslyn-dotnet-4.13.0)
- 继续使用现有兼容 API。实现 `field` 等新语法能力前，先评估最低 Roslyn/VS/SDK 版本及多版本打包需求，不为了单个动作让现有消费项目无法加载整个包。
- 对链接文件、跨目标框架和条件编译，在未来跨文件修复中检查全部受影响上下文。不能证明一致时缩小范围或不提供批量操作。

## 🧪 7. 验收与发布顺序

| 阶段 | 交付 | 完成门槛 |
| --- | --- | --- |
| P0：本次 | ZS0005、ZS2003 的单处及三个范围修复 | 包内导出/本地化、精确文本与语义、批量边界、原有诊断回归通过 |
| P1：SDK 操作审计 | 当前配置逐项对应的可用操作表、VS2026/CLI 样例工程 | IDE0009、命名和格式例外人工 UI 验收；记录哪些操作仅在 IDE 可用；补大文件及大量 using 的取消/耗时测量 |
| P2：现有资源复用 | ZS1304 确定性转换、CA1303 已有资源候选 | 资源身份、类型、culture、不可访问属性、键冲突和回退语义均有正反例 |
| P3：布局与限定名 | 安全区段 using 排序、using 别名消除、明确的分段检查 | 多种符号及预处理分支保持绑定；nameof 值不变；不改变字段初始化顺序 |
| P4：资源提取与较复杂重构 | 经验证的资源生成交互流程、属性/field 等有限修复 | 多文件预览、撤销、工具不可用、并发编辑和跨项目访问均有验收方案 |
| P5：持续覆盖 | 架构、异步、兼容性与资源所有权的诊断建议 | 有明确规则和人工复核指引，避免无法证明正确性的批量变更 |

每条新增规则必须带正例、反例、无修复情形、重复执行不再变更、无新增编译错误、注释/指令保留、生成代码例外和本地配置覆盖验证。开放 Fix All 前覆盖文档/项目/解决方案范围以及多处变更冲突；多文件修复还需验证未选中文档不变。

发布包须通过干净的 Cake 默认任务，并使用独立包缓存验证消费项目。VS2026 发布验收包括：灯泡出现、标题本地化、预览差异、单处应用、三个 Fix All 范围、撤销及重新分析。SDK/VS 升级后重新执行宿主兼容测试；CI 的编译通过不能替代 UI 验收。通过后递增包版本，再由维护者执行既有发布流程。

实现 API 的入口参考 [Microsoft Analyzer/Code Fix 教程](https://learn.microsoft.com/en-us/dotnet/csharp/roslyn-sdk/tutorials/how-to-write-csharp-analyzer-code-fix)。本方案不新增发布动作，也不改变当前规则的严重级别。
